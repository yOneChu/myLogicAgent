# 로직 검증 및 QA 프로세스 명세

본 문서는 수배로직의 정합성, 무결성, 문법 오류 및 무한 루프 가능성을 자동으로 검증하고 조치하는 오케스트레이션 상태 머신 기반 검증 프로세스를 정의합니다.

---

## 1. 파이프라인 상태 머신 (SUPPLY_LOGIC_PIPELINE_V2)

```text
PARSE ──OK──▶ VALIDATE ──OK/NEEDS_CONFIRM──▶ ANALYZE_LEGACY ──▶ BUILD ──▶ QA
  │BLOCKED                                                              │
  ▼                                                          validation_ready?
END_REPORT                                              ┌── true ───┐  false (retry<2)
                                                         ▼           │
                                                      REPORT   ◀─────┘(BUILD로 재진입)
                                                         │
                                                         ▼
                                                    END_SUCCESS
```

---

## 2. 세부 검증 단계 및 역할

### 1단계: PARSE (요청 해석, `REQUEST_PARSER`)
- 검증 요청 텍스트에서 대상 PID, 대상 Block No, 검증 조건/자재를 추출합니다.

### 2단계: VALIDATE (사양 마스터 검증, `DATA_VALIDATOR`)
- 특성코드 및 특성값이 마스터 데이터베이스에 존재하는지 확인합니다.
- 마스터 미등록 코드 발견 시 `NEEDS_CONFIRMATION` 상태로 설정하고 이슈 라벨(`REQUESTER_CONFIRMATION_NEEDED`)을 등록합니다.

### 3단계: ANALYZE_LEGACY (기존 로직 분석, `LEGACY_ANALYZER`)
- 기존 PID 로직의 ADDR 구획, GOTO 이동 경로, 사용된 다중 Pick 변수(`_1`, `_2` 등)를 파악합니다.

### 4단계: BUILD (로직 재구성, `LOGIC_BUILDER`)
- 검증 및 수정을 반영하여 로직 행(`logic_rows`)을 재구성합니다.

### 5단계: QA (정밀 검증 및 자동 피드백, `LOGIC_QA`)
- **자동 체크리스트 검사**:
  - `SPEC-CON` / `KEY-VAL` 짝 개수 일치 여부
  - `GOTO` 목적지 라벨의 존재 여부 및 무한 순환 루프 여부
  - 중복 조건에 의한 데드 코드(Dead Code) 생성 여부
  - 미정의 변수 참조 및 자재코드 자릿수 오타 검사
- **자동 피드백 루프**:
  - 확정 오류(`CONFIRMED` severity) 존재 시 `validation_ready = false`로 설정하고 `BUILD` 단계로 자동 돌려보내 수정을 요청합니다 (최대 2회).
  - 2회 재시도 초과 시 사람(설계자)에게 보고하도록 처리합니다.

### 6단계: REPORT (변경 보고 및 리포트 발행, `CHANGE_REPORTER`)
- 최종 검증 완료건에 대하여 `diff`(변경점 비교) 및 누적된 이슈 항목을 정리합니다.
- `output/reports/{PID명}_{날짜}/06_report.md` 리포트를 발행합니다.
