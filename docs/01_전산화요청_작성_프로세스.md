# 로직 전산화요청 작성 프로세스 명세

본 문서는 사용자의 수배로직 전산화 작성 요청(신규 로직 작성, 기존 로직 수정/추가)을 처리하는 표준 최적화 프로세스를 정의합니다.

---

## 1. 프로세스 개요

전산화요청 작성 파이프라인은 요청 수신부터 DB 데이터 추출, 수배 사양 검증, 로직 테이블 구성 및 최종 보고서 발행까지 standard workflow를 따릅니다.

```text
[1. DB 추출 및 레거시 확보] ➔ [2. 로직 파싱 및 전처리] ➔ [3. 사양 검증 및 로직 작성] ➔ [4. 최종 리포트 발행]
```

---

## 2. 세부 단계별 수행 절차

### 1단계: DB 추출 및 데이터 확보 (Data Extraction)
- **실행 방식**: `reference/db_metadata/pid_query.sql`을 기준으로 실행 SQL(`scripts/db_query/query.sql`)을 생성하고, 추출 스크립트를 수행합니다.
- **저장 위치**:
  - CSV 파일: `legacy_logic/{PID명}_{YYYYMMDD}.csv` (`utf-8-sig` 인코딩 적용)
  - Excel 파일 (필요시): `output/excel/{PID명}.xlsx`

### 2단계: 로직 파싱 및 전처리 (Parsing & Preprocessing)
- **구조 분석**: 로직의 컬럼 구조(`ADDR`, `SPEC`, `CON`, `KEY`, `VAL`, `GOTO`, `REMARKS`)를 읽어 파싱합니다.
- **세션 디렉토리 생성**: `work/{PID명}_{세션ID}/` 디렉토리를 생성하고 아래 문서를 기록합니다.
  - `01_parse.md`: 요청 원문 및 대상 PID 분석 요약
  - `03_legacy_analysis.md`: 기존 로직의 ADDR 흐름(INIT, MAIN 등), 수배 자재 매핑표 정리

### 3단계: 사양 검증 및 로직 작성 (Validation & Building)
- **특성코드/특성값 검증**: `reference/master_data/`의 마스터 데이터와 대조하여 유효한 사양인지 확인합니다.
- **로직 행 구성**:
  - `SPEC`/`CON` 조건을 작성할 때 부정(`!`), 목록(`,값,`), 와일드카드(`?값?`) 연산자를 준수합니다.
  - Pick 로직(`EL_P...` / `SH_P...`), 수량/주석 로직(`...` / `SH_...`), 계산 로직(`CAL_...` / `SH_AUTO_...`) 문법을 준수합니다.

### 4단계: 결과 보고서 및 최종 산출물 생성 (Reporting)
- **산출물 위치**: `output/reports/{PID명}_{YYYYMMDD}/`
- **주요 내용**:
  1. **로직 기본 정보**: 대상 PID, Block No, 로직 구획 설명
  2. **수배 사양 매핑표**: 사양 조건별 산출 자재코드 및 설명
  3. **확인 필요 사항 (`REQUESTER_CONFIRMATION_NEEDED`)**: 자재코드 오타 의심, 마스터 부재 특성 등 요청자 확인이 필요한 사항 명시
