# PLM 로직 Editor 문법 규칙 (워크스페이스 전용)

로직 데이터는 엑셀 형태와 유사하며, 좌→우, 상→하 순서로 읽는다. 한 행 = 하나의 규칙이다.

## 컬럼 구조
`ADDR`, `SPEC{n}`, `CON{n}`, `KEY{n}`, `VAL{n}`, `GOTO`, `REMARKS`
- 실제 시스템 확인 결과: SPEC/CON은 최대 30쌍, KEY/VAL은 최대 20쌍까지 존재. 실무에서는 이보다 훨씬 적게 사용되는 경우가 많다.

## SPEC / CON (조건 쌍)
- SPEC: 조건으로 삼을 특성코드 또는 수식 / CON: 해당 특성코드의 특성값
- SPEC/CON은 항상 짝(개수 일치). 한 행에 여러 쌍이면 AND 조건.
- CON 표기법 4종: 단일값(`KR00`) / 목록(`,GTLX,GTSS,`) / 와일드카드(`?GT?`) / 비교식(`>1100`)
- 부정(`!`)은 단일값·와일드카드 앞에 붙여 사용 가능 (`!N`, `!?KS?`)
- SPEC만 있고 CON이 빈 칸인 경우, 그 의미를 임의로 단정하지 않고 [확인 필요] 라벨을 표시한다.
- CON의 값은 빈칸일 수도 있다.
- SPEC이 공백인데 CON에 값이 있으면 오류이다.

## KEY / VAL (산출 쌍)
- KEY: 결과를 반영할 대상 / VAL: 대상에 입력될 값(주로 자재번호). 항상 짝.
- 주석 신규 출력: `KEY=L_CMT`, `VAL=주석 문구`
- 기존 주석에 이어붙임: `KEY=CMT`, `VAL={CMT}{L_CMT}`
- 계산 로직 호출: `KEY=CALL`, `VAL=계산 로직 PID`
- KEY-IN 값: 타입이 KEY IN인 특성(예: `EL_ECBB`)은 주문 시 직접 입력되며, 특성값 마스터에 열거값이 없다. 수식에서는 `EL_` 접두로 사용.
- KEY에는 CALL, VAL에 'EL_P' 등 값이 입력되면, VAL값의 PID를 호출한다는 의미이다.

## ADDR / GOTO (분기)
- GOTO: 'STOP'이면 해당 행에서 멈추고, 그 이외의 값이면 ADDR에 동일한 값인 행으로 이동하며 그 사이에 있는 행들은 건너뛴다.
- ADDR: 흐름 라벨/분기 시작점 (예: `MAIN`, `INIT`)
- GOTO로 분기한 이후의 줄에는 동일 조건을 재입력할 필요가 없다.

## REMARKS
- 참고용 메모. 실제 로직 동작(자재 선택 등)에 영향을 주지 않는다.
- 관습적으로 "선택된 자재가 어떤 용도·사양 조합에 대응하는지"를 사람이 읽을 수 있도록 적는다.

## 작성 시 지켜야 할 것
- 다중 Pick 변수(_1, _2…) 번호가 비어 있어도(예: _3 누락) 그것이 오류가 아닐 수 있다 — 실사용 사례로 확인된 정상 패턴이다.
- ADDR, REMARKS의 열의 값 제외하고 나머지 열의 SPEC + CON + KEY + VAL + GOTO 값들의 조합과 동일한 중복된 행이 존재하면 문법에 어긋난다.

## 지침
- 문제가 있거나 중복된 행이 있다면 그 라인을 알려줘
