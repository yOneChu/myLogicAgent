# 수배로직 전산화 및 검증 차세대 통합 워크스페이스 (new_Workspace)

## 2. 주요 프로세스 요약

### ① 전산화 요청 작성 프로세스 (`docs/01_전산화요청_작성_프로세스.md`)
1. **요청 수신 및 DB 추출**: 요청 대상 PID의 기존 로직 데이터를 DB에서 추출(`legacy_logic/`에 저장).
2. **로직 파싱 및 데이터 구조화**: 로직 조건(`SPEC`/`CON`), 결과(`KEY`/`VAL`), 분기(`ADDR`/`GOTO`) 추출 후 `work/` 세션에 파싱 문서 생성.
3. **규칙 기반 로직 작성**: 마스터 사양 데이터와 수배자료 근거를 바탕으로 신규/수정 행 구성.
4. **결과 문서화**: 로직 테이블, 사양 대응표, 특이사항이 포함된 보고서 생성.

### ② 로직 검증 및 QA 프로세스 (`docs/02_로직_검증_및_QA_프로세스.md`)
1. **요청 해석 및 기본 검사 (`REQUEST_PARSER` & `DATA_VALIDATOR`)**: 특성코드 및 특성값 유효성 검증.
2. **기존 로직 파악 (`LEGACY_ANALYZER`)**: 기존 흐름 분석 및 영향도 평가.
3. **무결성 정밀 검증 (`LOGIC_QA`)**:
   - `SPEC-CON` / `KEY-VAL` 짝 개수 일치 검사
   - `GOTO` 분기 목적지 존재 여부 및 무한 루프 검출
   - 데드 코드(Dead Code) 및 미정의 변수 참조 검출
   - **자동 수정 루프 (QA ↔ BUILD)**: 확정 오류 발생 시 최대 2회 자동 수정 재시도.
4. **변경 보고 및 최종 리포트 발행 (`CHANGE_REPORTER`)**: 최종 diff 및 확인 필요 사항(`REQUESTER_CONFIRMATION_NEEDED`) 정리 후 `output/reports/`에 리포트 저장.

## 3. 작업 규칙 및 원칙

1. **사실 기반 작성**: 모든 산출물과 판단은 DB 데이터, 마스터 데이터, 수배자료 근거에 기반합니다.
2. **구조화된 파일 관리**: 모든 중간 산출물은 `work/{세션ID}/` 하위에 보관하며, 최종 결과물만 `output/`으로 발행합니다.
3. **인코딩 표준**: 모든 CSV 파일은 Excel 호환성을 위해 `utf-8-sig` 인코딩을 사용합니다.
